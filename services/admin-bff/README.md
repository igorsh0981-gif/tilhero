# admin-bff

**Bounded context:** сессии сотрудников в браузере, CSRF, rate limit, RBAC и step-up TOTP, actor-токены к доменам и агрегация API для admin-web TilHero. Своих данных в БД нет; в Redis — сессии, кэш principal и счётчики лимитов.

Стек: Node 22, Fastify 5, `@tilhero/ts-common` (контекст трассировки, ErrorBody, внутренний JWT v2 EdDSA с `actor`, circuit breaker, health, единый лимитер), ioredis. Порт **8002**.
Публичный контракт — `packages/contracts/src/admin.ts` (единственный источник типов; спринт 3 — раздел «Контент и диагностика» и `content.ts`; спринт 4 — раздел «ИИ, контроль диалогов, затраты» и `ai.ts`; спринт 5 — раздел «Память, словарь курса, чтение», `content.ts` ReadingPayload/GlossaryEntry; спринт 6 — раздел «Игра и герои» и типы игры `bff.ts`), внутренние — `docs/sprint2/INTERNAL_API.md` §4, `docs/sprint3/INTERNAL_API.md` §1.5, §2.5, §6, `docs/sprint4/INTERNAL_API.md` §1.5, §2.5, §3.4, §6, `docs/sprint5/INTERNAL_API.md` §1.11, §2.1, §2.5, §3.2, §7, `docs/sprint6/INTERNAL_API.md` §1.11, §10, §12. Форк admin-bff «Бот турист» (aievent), сокращённый до объёма TilHero.

## Как это работает

```
браузер ──▶ admin-web (Caddy) ──/admin/v1/*──▶ admin-bff ──внутренний JWT v2 (kid=iss=admin-bff, aud=<домен>,
            один origin, cookie first-party       │          actor {id, role, name, permissions})──▶ admin-identity, user-admin,
                                                  │                                                   identity-consent, support, audit,
                                                  └── Redis: sess:<sha256(id)>, principal:<staff_id>, rl:*   experience-config, notifications,
                                                                                                             catalog, diagnostics (спринт 3),
                                                                                                             ai-gateway, lessons, assessment (спринт 4),
                                                                                                             memory (спринт 5)
```

- **Публичного домена нет.** admin-web проксирует `/admin/v1/*` на `http://${{admin-bff.RAILWAY_PRIVATE_DOMAIN}}:8002`; один origin, CORS не включается.
- **Сессия:** cookie `__Host-tilhero_admin` (Secure, HttpOnly, SameSite=Strict, Path=/, без Domain) с непрозрачным id (32 случайных байта). В Redis ключ — `sha256(id)`, HASH `{staff_id, session_version, created_at, last_seen_at, step_up_until, csrf_token, ip_hash, ua_hash, impersonating, superseded_until}`. Бездействие 30 мин и абсолютный срок 8 ч → `401 SESSION_EXPIRED`. При входе id всегда новый, прежняя cookie браузера удаляется (session fixation). Другой User-Agent с той же cookie → сессия отзывается.
- **Ротация id** (смена пароля, step-up) — атомарный Lua: старая сессия должна существовать и не быть замещённой (параллельный logout побеждает → `401`). После step-up старый id ещё 15 с действует **без** step-up и без продления; logout по любому из двух id удаляет обе. Повторная ротация замещённого id (две вкладки) → `409 SESSION_ROTATED` **без** Set-Cookie (TOTP-код и пароль не тратятся); клиент повторяет запрос один раз.
- **Фоновые запросы:** `X-Background: 1` — запрос обслуживается, но сессию не продлевает.
- **Выход безотказный** (ревью T2-1): `POST auth/logout` — уровень `sessionOnly()`: cookie → сессия → срок → User-Agent → CSRF/Origin, **без** principal admin-identity и без лимитов. Сессия (вместе со связанным ротацией id) удаляется и cookie стирается до обращения к admin-identity; его `/internal/v1/auth/logout` (аудит) — best effort, при недоступности — резервная запись `auth.logout` в audit (actor — из кэша principal или по сессии). Регресс-тест: admin-identity недоступен и кэш principal истёк → 204, та же cookie → 401. Redis недоступен (ревью T2-10): Origin проверяется до Redis, cookie стирается всё равно, ответ `503 SESSION_NOT_REVOKED {service: "session-store"}` (сессия на сервере могла остаться — admin-web предупреждает сотрудника; аудит выхода не пишется).
- **Отзыв:** principal (`GET admin-identity /internal/v1/staff/{id}/principal`, строгая проверка формы) кэшируется в Redis ≤ 30 с; статус ≠ ACTIVE, другая `session_version`, 404/403 → `401 SESSION_REVOKED` и удаление сессии. Изменения через BFF (смена пароля, PATCH сотрудника, сбросы, применённый approve) сбрасывают кэш цели сразу.
- **CSRF:** все не-GET — `X-CSRF-Token` = `Me.csrf_token` (сравнение за постоянное время) + `Origin` = `ADMIN_ORIGIN` (без Origin — только `Sec-Fetch-Site: same-origin`) → иначе `403 CSRF_INVALID`. Шаги входа (до сессии) — проверка Origin.
- **RBAC декларативно:** каждый маршрут `/admin/v1/*` объявляет `publicAuth` / `authenticated` / `requirePermission(...)` / `requireRole(...)` и при необходимости `requireStepUp()`; маршрут без объявления или без схемы ответа не регистрируется (приложение не стартует). Проверка — в `onRequest`, **до** разбора тела и вызова домена; домены проверяют `actor.permissions` повторно.
- **Step-up** (`POST /admin/v1/auth/step-up {code}` → новый id с `step_up_until = now + 5 мин`) — по шапке admin.ts: публикация и снятие «Что нового», активация и сброс шаблона, расписание и остановка рассылки, активация и откат конфигурации, раскрытие Telegram ID, все команды по сотрудникам, ролям и заявкам; спринт 3 — публикация, снятие и откат контента, подтверждение прав медиа, решение по заявке ученика, правка языков и пар, публикация версии теста диагностики; спринт 4 — публикация, канарейка (установка и снятие) и откат версии агента, правка модели и цен, бюджет и аварийная остановка ИИ, переоценка, решение по апелляции; спринт 5 — ручная правка карточки памяти ученика (`memory.manage`; словарь курса `glossary.manage` — без step-up); спринт 6 — активация и откат правил игры, публикация героя, публикация и снятие предмета магазина, публикация и отмена события недели (`game.publish`), ручная операция, обратная запись и возврат покупки (`wallet.adjust`) → иначе `403 STEP_UP_REQUIRED {permission}`.

- **Лимиты** (единый лимитер ts-common, GCRA в Redis, общий для реплик): вход 10/мин с IP (IPv6 — по /64) и 5/мин на email (в ключе — хеш с суточной солью); шаги по challenge 30/мин с IP и 5/мин на challenge; step-up и смена пароля 5/мин на сотрудника; команды (не-GET) 60/мин; всё 300/мин на сотрудника → `429 RATE_LIMITED {policy, retry_after}` + `Retry-After`.
- **Ошибки:** ErrorBody. 4xx доменов — как есть (код, статус, details: `TEMPLATE_INVALID {fields}`, `RELEASE_NOTE_TRANSLATION_MISSING {missing}`, `CAMPAIGN_*`, `SUPPORT_INVALID_TRANSITION`, …); недоступность / таймаут / 5xx / битый или испорченный ответ / отказ внутренней авторизации → `503 UPSTREAM_UNAVAILABLE {service}`. Раскрытие: `503 AUDIT_UNAVAILABLE` identity-consent передаётся с этим кодом (значения нет). Сбой Redis → 503 (fail-closed).
- **Строгая проверка ответов доменов** (`src/codec.ts`, `src/contract.ts`): одно описание поля даёт и проверку значения, и схему ответа (fast-json-stringify). `C.obj<T>()` требует ровно ключи типа admin.ts — расхождение с контрактом ломает `tsc`. Лишние поля доменов отбрасываются; не тот тип, неизвестное значение перечисления, время без зоны → 503 (в лог — только путь поля). Тесты проверяют каждый 2xx-ответ до сериализации строгим Ajv (`x-contract-required` → `required`).
- **Защита PII в ответах** (наследник A43 `redactSensitive` aievent — там удалён в спринте 7 вместе с AI-перепиской): `telegram_id_masked`, не похожий на маску (`••••••789`), заменяется на `null` — полный Telegram ID из read-модели наружу не уходит никогда; `username` — полный только сотруднику с `users.sensitive.read`, иначе маска `ig•••81` (короче 5 символов — `•••`, без «@») (маскирует user-admin по actor; если домен вернул полный — маскирует BFF: реестр, карточка, дети, опекун, сводка в тикете; ревью T2-3); подпись тестового получателя с ≥ 5 цифрами подряд → 503; служебные поля (`search_text`, `cursor`, `chat_ids`, `ticket_id` эскалации, каталог прав `/roles`) отбрасываются; значение reveal — только в ответе (`Cache-Control: no-store`).

Автор сида `00000000-0000-4000-a000-000000005eed` (не сотрудник) — имя «Сид (начальное наполнение)» без lookup. Заявки учеников: реестр — только `media.rights` (ревью: персональные данные; число новых заявок для обзора — `content/summary`, dashboard.read | content.read); название, ссылка и комментарий — только текст (управляющие символы вычищаются; ссылка не открывается и не скачивается). Коды catalog/diagnostics — как есть: `CONTENT_INVALID {errors}`, `SELF_REVIEW`, `DRAFT_EXISTS {version}`, `VERSION_CONFLICT {payload_hash}`, `CONTENT_IN_USE {refs}`, `ROLLBACK_TARGET_INVALID`, `AUDIO_INVALID {reason}`, `MEDIA_REQUEST_DECIDED`, `PAIR_NOT_READY {missing}`, `DIAGNOSTIC_TEST_NOT_FOUND`, `TEST_INVALID {errors}` …
- **Лимит тела:** 64 КБ по умолчанию; создание и правка версии агента (`POST|PATCH /ai/agents/{id}/versions…`) — 128 КБ (инструкции ≤ 20 000 + правила ≤ 10 000 символов, кириллица — 2 байта, плюс JSON Schema); черновик и правка версии контента (`POST /content/{kind}`, `PUT …/versions/{v}`) — 256 КБ (лимит тела catalog); загрузка аудио `POST /content/blobs` — 4,5 МБ (JSON base64 ≤ 3 МБ; как `UPLOAD_MAX_BYTES` catalog) → больше — `413 PAYLOAD_TOO_LARGE` без вызова домена. Предпросмотр `GET /content/blobs/{id}` отдаёт байты catalog с его типом только если это `audio/mpeg|audio/ogg|audio/mp4` и ≤ 3 МБ (иначе 503), `Cache-Control: no-store`, `nosniff`.
- **Языковые пары:** `PairCard` = catalog + diagnostics: `readiness.diagnostic_test` — опубликованный тест пары из `GET /admin/v1/diagnostics/tests` (`dx-en-adult@1`, взрослый приоритетнее детского), `learners` — `GET /admin/v1/diagnostics/pairs`; diagnostics недоступен — значения catalog (null / 0), экран открывается. Публикация пары (`status: published`, пара ещё не опубликована): нет опубликованного теста диагностики → `422 PAIR_NOT_READY {missing: [...готовность catalog, "diagnostic_test"]}` до вызова catalog (изменение не применяется; недостающее по контенту — по карточке catalog: курс, уроки, рубрики, локализации); diagnostics недоступен → 503 (fail-closed); тест есть — решает catalog.
- **ИИ (спринт 4, ai-gateway `/admin/v1/ai/*` — пути совпадают):** реестр 17 агентов, карточка с версиями, версия (инструкции, правила, JSON Schema вывода — как есть, их проверяет ai-gateway), золотые тесты (`input.context` — JSON-объект как есть, проверки `GoldenCheck` — строго по виду), прогоны (202 + опрос), публикация/канарейка/откат, модели и цены, провайдер, бюджет, аварийная остановка, затраты. Имена: `published.published_by` → `published_by_name`, версии — `author_id` → `author_name`, `published_by` → `published_by_name` (сид `00000000-0000-4000-a000-000000005eed` — «Сид (начальное наполнение)»); идентификаторы, которых нет в admin.ts, клиенту не уходят. Правка черновика — `If-Match` передаётся в ai-gateway как есть (`409 VERSION_CONFLICT` решает домен). Коды домена — как есть: `TESTS_REQUIRED`, `TESTS_FAILED {case_ids}`, `DRAFT_EXISTS {version}`, `VERSION_NOT_DRAFT`, `VERSION_CONFLICT`, `NO_PREVIOUS_VERSION`. **Ключ провайдера ИИ** (только переменная ai-gateway) в админку не попадает никогда: любой ответ ai-gateway — тело, ErrorBody 4xx, блок дашборда, вызовы сессии в карточке — с полем, похожим на ключ (`api_key`, `x-api-key`, `secret`, `authorization`, `anthropic_api_key` …), или строкой вида `sk-…` (≥ 20 символов хвоста) → `503 UPSTREAM_UNAVAILABLE {service: ai-gateway}` (блок — недоступен), в лог — `PROVIDER_KEY_IN_RESPONSE` и путь поля без значения. `GET /ai/provider` — только «задан / не задан» и код последней ошибки.
- **Контроль диалогов (спринт 4):** журнал `GET /qa/sessions` = lessons `GET /admin/v1/lesson-sessions` (фильтры как есть, ≤ 50 строк на страницу) + сводка оценок assessment одним запросом `GET /admin/v1/evaluations/summary?session_id=…` (`passed` и флаг `human_review` — по актуальной оценке с учётом переоценки, `appealed` — есть апелляция, `flagged` — флаг QA; сводка недоступна — значения lessons, в лог предупреждение) + модели, стоимость и p95 строки одним пакетным вызовом ai-gateway `GET /admin/v1/ai/usage/by-session?session_id=…` (≤ 50, таймаут `DASHBOARD_TIMEOUT_MS`, без повторов) только для сессий, где ИИ мог работать (`ai_mode = full` или флаги `ai_used`/`ai_unavailable`); сессия выбором реплик или без вызовов — `models: [], cost_usd: 0, p95: null`; ai-gateway недоступен, ответил ошибкой (404/503) или мусором — `cost_usd: null` (стоимость неизвестна, не 0), `models: []`, `p95: null`, журнал открывается, в лог — предупреждение. В карточке p95 — по успешным вызовам сессии (ближайший ранг), блок ai-gateway недоступен — `cost_usd: null`.  Фильтр `flag`: флаги lessons (`ai_used`, `ai_unavailable`, `hints`, `human_review`, `failed`) передаются в lessons; `appealed`, `flagged` ведёт assessment — lessons их не фильтрует, BFF фильтрует строки после сводки (все флаги — ещё и после сводки): за запрос до 3 страниц lessons с `limit` = недостающее, страница может быть короче `limit`, `next_cursor` — курсор lessons (пропусков нет); без сводки фильтр по `appealed`/`flagged` невозможен → `503 {service: assessment}`. Карточка `GET /qa/sessions/{id}` — три независимых блока параллельно: lessons `GET /admin/v1/lesson-sessions/{id}`, assessment `GET /admin/v1/evaluations?session_id=`, ai-gateway `usage?session_id=`; недоступный или испорченный блок → `null` и `errors[service] = код` (`UPSTREAM_UNAVAILABLE`, `UPSTREAM_BAD_RESPONSE` или код домена), сессии нет в lessons → `404` как есть. `user_ref` = первые 8 hex `sha256(user_id)` — сам `user_id` сотруднику не отдаётся (если lessons отдал готовый `user_ref` — он); текст реплик в карточку не попадает (только метаданные). Оценки — цепочка по `created_at` (новая последней), `created_by` (`system` | staff_id) → `created_by_name` (система — null), `flags[].by` → `by_name`. Реплики `POST /qa/sessions/{id}/transcript {reason ≥ 10}` — только `qa.transcripts`, аудит `qa.transcript_viewed` пишет lessons по actor; тексты — только в ответе (`no-store`), не в логах. Флаг (qa.read), переоценка и решение по апелляции (qa.review + step-up), «взять» (qa.review) → assessment; `appeal_id` / `new_evaluation_id` по умолчанию `null`; коды `EVALUATION_SUPERSEDED`, `SELF_REEVALUATION`, `APPEAL_EXISTS` … — как есть. Апелляции: `taken_by`/`decided_by` → `*_name`; текст ученика — без управляющих символов. Вызовы ИИ `GET /ai/usage`: `costs.read` — любые фильтры, `qa.read` — только с `session_id` (иначе `403 PERMISSION_DENIED {permission: costs.read}` до вызова домена).
- **Память, словарь курса, чтение (спринт 5).** *Словарь курса* — catalog `/admin/v1/glossary*` (пути совпадают): список (`content.read`; очередь переводов ИИ — `review_status=pending`), карточка с историей, счётчики `glossary/stats?pair_id=` (`dashboard.read | content.read` → `GlossaryStats`), создание / правка (`If-Match: updated_at` — в catalog как есть, неверный формат — 422 до домена; без него — `428 IF_MATCH_REQUIRED`, устаревший — `409 VERSION_CONFLICT` домена) / решение по переводу ИИ (`correct` — только с `gloss`, иначе 422 до домена) / архив (`DELETE` с телом `{reason}` → 204) — `glossary.manage` без step-up. Имена: `updated_by` → `updated_by_name`, `history[].by` → `by_name` (сид — «Сид (начальное наполнение)», `by: null` — система); `updated_by`, `history[].by`, `override.by` — поля admin.ts, уходят как есть; `before`/`after` истории — JSON как есть. Команды со step-up (активация и откат правил, публикация героя, публикация и снятие предмета, публикация и отмена события, ручная операция, обратная запись, возврат покупки) получают заголовок `X-Step-Up: ok` — gamification проверяет step-up в домене (защита в глубину); остальным заголовок не передаётся. Idempotency-Key обязателен у создания предмета, события и ручной операции (`422 IDEMPOTENCY_KEY_REQUIRED` до домена), у прочих команд — передаётся, если прислан. `If-Match` черновика правил — как есть (неверный формат — 422; `409 DRAFT_CONFLICT` решает домен). Ответы — строгие кодеки `src/contractGame.ts`: ровно ключи admin.ts (сверка при `tsc`, перечисления входа — тоже), лишнее отбрасывается, чужое значение перечисления, время без зоны, отрицательный баланс, тема-CSS вместо ключа токена → `503 UPSTREAM_UNAVAILABLE {service: gamification}` (в лог — путь поля без значения). `AdminGameImage.url` собирает BFF (`/admin/v1/game/assets/{asset_id}/content`), значение домена не берётся. `StaffRef` — домен отдаёт `{staff_id, name}` (имя из actor-токена) или только `staff_id`; имя — admin-identity staff/lookup, не найден — имя домена; `system` — «Система», сид — «Сид (начальное наполнение)». `payload` версии правил: активная и архивная — строго `GameRules`; черновик — JSON-объект как есть (≤ 64 КБ): он ещё не проверен, ошибки с путями даёт `validate` (`422 RULES_INVALID {errors: [{path, code}]}`). `diff[].from/to` — JSON как есть (нет поля — null). *Картинка:* `POST game/assets?purpose=hero_stage|shop_item|badge` — сырое тело `image/webp | image/png` (парсер `image/*` действует только на этом маршруте, на прочих — 415): поток до 300 КБ (больше — `413 ASSET_TOO_LARGE {max_bytes}` без вызова домена, тело дальше не читается; без сессии и права тело не читается вовсе), формат по сигнатуре и размеры по заголовку (PNG IHDR, WebP VP8/VP8L/VP8X; `src/gameImage.ts`) → иначе `422 ASSET_INVALID {reason: content_type | empty | signature | type_mismatch | dimensions}`; байты уходят в gamification как есть с тем же типом. `GET game/assets/{asset_id}/content` (game.read, черновые тоже) — байты gamification только `image/webp|image/png` ≤ 300 КБ с совпадающей сигнатурой (иначе 503), `nosniff`, `no-store`, `inline`. Коды gamification — как есть: `RULES_INVALID {errors}`, `RULES_NOT_VALIDATED`, `DRAFT_CONFLICT`, `HERO_IN_USE {learners}`, `EVENT_OVERLAP {event_id}`, `BALANCE_NEGATIVE`, `ALREADY_REVERSED`, `ASSET_TOO_LARGE`, `ASSET_INVALID {reason}`, `*_NOT_FOUND`. *Без `GAMIFICATION_URL`* (необязательна во всех окружениях) — маршруты игры отвечают `503 UPSTREAM_UNAVAILABLE {service: gamification}` (после проверки сессии, права и step-up), блок обзора `game` недоступен, остальная админка работает; при старте — предупреждение в лог.
- **Агрегация:** карточка ученика = user-admin + support `GET /admin/v1/support/tickets?user_id=&limit=20` (без `support.read` → `tickets: null` без вызова support; support недоступен — тоже `null`). Тикет поддержки = support + сводка ученика из user-admin (`?q=<uuid>&limit=1`, только при `users.read`). Дашборд — 10 независимых блоков параллельно (спринт 5: `memory` — memory `GET /admin/v1/memory/stats?period=` + очередь переводов ИИ catalog; спринт 6: `game` — gamification `GET /internal/v1/admin/game/overview?period=7d|30d` → `GameStats`: XP и тилы, использованные заморозки, выполненные задания, активное событие — то, что заканчивается раньше всех; итогов «за сегодня» у gamification нет — при `period=today` блок за 7 дней, `GameStats.period: 7d`) (спринт 3: `content` — catalog `GET /admin/v1/content/summary`, `diagnostics` — diagnostics `GET /admin/v1/diagnostics/stats?period=`; спринт 4: `lessons` — lessons `GET /admin/v1/lesson-sessions/stats?period=` + assessment `GET /admin/v1/assessment/stats?period=` (`appeals_open`, `human_review_open`; доступен, только если ответили оба — иначе `service` первого недоступного), `ai` — ai-gateway `GET /admin/v1/ai/usage/summary?period=month` (расход месяца против потолка)) (таймаут `DASHBOARD_TIMEOUT_MS`, без повторов): источник недоступен, ответил ошибкой или мусором → `{available: false, data: null, service}`, ответ всегда 200.
- **Аудит действий BFF** (`POST audit /internal/v1/records` с actor): только `dev.impersonate` (без записи режим не включается) и резервный `auth.logout`, если admin-identity недоступен. Остальное аудируют домены.
- **Логи:** JSON, trace_id и псевдоним сотрудника; access-лог — шаблон маршрута (не URL с `q=@username`). Пароли, коды, challenge, секрет MFA, временный пароль, cookie, CSRF, email, Telegram ID, имена, причины и тексты вычищаются (redact pino + рекурсивный `scrub`).

## Отклонения и договорённости

- Lookup имён — `GET /admin/v1/staff/lookup` (так реализовал admin-identity); в INTERNAL_API §1 записан `/internal/v1/staff/lookup`.
- `GET /admin/v1/notifications/test-recipients` — права `notif.templates.manage` **или** `notif.campaigns.manage` (тест нужен и шаблонам, и рассылкам; в admin.ts право маршрута не указано).
- `POST …/campaigns/{id}/estimate` и `…/tickets/{id}/take` принимают только пустое тело (`{}` или без тела; лишнее поле → 422).
- Необязательное (`?:`) поле контракта, пришедшее от домена как `null`, в ответ не попадает (например, `SlaPolicy.updated_by`).
- `Campaign.last_error`: если notifications прошлой версии поля не отдаёт — `null` (испорченное значение — по-прежнему 503).
- Спринт 3: `PUT /admin/v1/language-pairs/{pair_id}` проверяет опубликованный тест диагностики до catalog (тест живёт в diagnostics, договорённость с координатором); объединённый `missing` в этом случае — по карточке catalog (точный список catalog даст, когда тест появится). Параметры путей в коде — `:pairId`, `:blobId` (в admin.ts — `{pair_id}`, `{blob_id}`); `test-run` и `rights-approve` — статические пути с видом (`content/scenario/…`, `content/media_asset/…`), для других видов — 404 маршрута. Имя автора сида — только по-русски («Сид (начальное наполнение)»): язык интерфейса сотрудника BFF не знает.
- Спринт 4, пути доменов, не записанные в INTERNAL_API: статистика уроков для обзора — lessons `GET /admin/v1/lesson-sessions/stats?period=` (LessonStats без `appeals_open`, `human_review_open`), счётчики оценок — assessment `GET /admin/v1/assessment/stats?period=` (из ответа берутся `appeals_open`, `human_review_open`); пакетная сводка журнала — assessment `GET /admin/v1/evaluations/summary?session_id=…` (≤ 100); журнал, карточка и реплики — lessons `/admin/v1/lesson-sessions[/{id}[/transcript]]`; оценки сессии — assessment `GET /admin/v1/evaluations?session_id=` → `{items: EvaluationCard[]}` (с `created_by`, `flags[].by`); флаг и переоценка — `POST /admin/v1/evaluations/{id}/flag|reevaluate`; апелляции — `GET /admin/v1/appeals`, `POST /admin/v1/appeals/{id}/take|decide`.
- Спринт 4: `GET|POST|PATCH …/versions/{v}` → `AgentVersionView` (admin.ts; с `updated_at` — If-Match правки, и `canary`), карточка агента — `AgentDetail`. `PUT /ai/budget` принимает и необязательный `ai_enabled` (аварийная остановка — своей командой `emergency-stop`, домен вправе отклонить). `DELETE /ai/golden-cases/{id}` — статус домена: 204 или 200 с `GoldenCase` (archived_at). Блок обзора `lessons`: период в ответе lessons принимается и в форме `day|week|month`, в обзоре — запрошенный (`today|7d|30d`).
- `ApprovalDecision.temporary_password` — решающему для `staff.privileged_reset`, `staff.create_privileged`, `staff.role_grant`, `staff.reactivate_privileged` (null домена → ключа нет); `StaffCreated.temporary_password` для привилегированной роли — `null` автору.
- Спринт 5: запасной источник счётчика при 404 `glossary/stats` — поле `ai_glosses_pending` сводки `content/summary` (договорённость с координатором; catalog реализовал `stats`). Без `actor_id` у строки истории (memory прошлой версии) имя сотрудника — `actor_name` memory (из actor-токена на момент правки). `GlossaryCreate`: все ключи обязательны, как в admin.ts (`part_of_speech`, `example_en`, `reason` — `null`); `GlossaryPatch.override` — `gloss` и `example_en` обязательны. `memory/analytics` без `pair_id` — решает memory (по умолчанию `ru-en`); `period` по умолчанию `30d`. Параметры путей в коде — `:entryId`, `:userId`, `:cardId`.
- Спринт 6, пути и формы, не записанные в INTERNAL_API: байты картинки для админки — gamification `GET /internal/v1/admin/game/assets/{asset_id}/content` (в §1.11 записаны только метаданные `GET /assets/{id}`; gamification маршрут реализовал — байты и черновых картинок); реестр операций принимает и `limit` (1..100, как у gamification; admin-web запрашивает по 50); `StaffRef` принимается и как строка `staff_id`. Блок обзора `game`: у `GameOverview` периодов «today» нет — при `period=today` запрашивается и показывается 7d. Маршрут картинки при `GAMIFICATION_URL` не задана — `503 UPSTREAM_UNAVAILABLE {service: gamification}` (не `GAME_UNAVAILABLE` telegram-bff: admin-web обрабатывает недоступность доменов единообразно). Комментарий публикации героя, предмета и события — 3..300 символов (admin.ts задаёт ≥ 10 только для правил; gamification принимает и без комментария, admin-web требует ≥ 10). Блок обзора `game` gamification отдаёт только с `game.read` (`/overview`): роли без него (read_only, communications, qa_analyst) видят блок недоступным. Параметры путей в коде — `:version`, `:code`, `:id`, `:assetId`, `:userId`, `:opId`, `:purchaseId`.
