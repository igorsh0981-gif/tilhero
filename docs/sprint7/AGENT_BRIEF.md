## Правила работы
- **Только свои каталоги** (указаны в задаче). `packages/*`, корневые `pyproject.toml`/`package.json`/`uv.lock`/`package-lock.json`, `infra/*`, `.github/*` НЕ трогай. Схемы событий, лимиты, CI и Railway уже настроены координатором. Нужно изменение общего кода, контракта или зависимости — опиши в отчёте («Запросы к общему коду»), у себя сделай минимальный обход.
- **Зависимости установлены.** Не запускай `uv add`/`uv lock`/`npm install <pkg>`. Картинки проверяй по сигнатуре байтов и заголовку размеров (webp VP8/VP8L/VP8X, png IHDR) своим кодом, без Pillow.
- **Социальное не меняет учёбу.** Лиги, дуэли и парные уроки дают только игровые награды; учебное состояние меняет независимый оценщик по индивидуальным доказательствам каждого ученика.
- **Приватность.** Наружу — только ник, герой, XP, место, разрешённые значки и `member_id`. Никогда — `user_id` в API ученика, имя, Telegram, возраст, ответы, ошибки, покупки. Чужой отчёт, ответы и ошибки не показываются никому, кроме владельца.
- **Деньги.** Минуты парных уроков учитываются, но не списываются (спринт 8). Ставок тилами нет.
- **Дети 6–13:** без друзей и общей лиги, всё — только внутри семьи; парный урок — только выбор реплик; мягкие тексты на «ты» без сравнений; push ребёнку нет.
- **Блокировки и санкции** проверяются в домене каждой социальной команды (заявка, вызов, приглашение, лига).
- **Общие правила:**
  - UUID для сущностей учеников; `user_id`/`staff_id` — только из токена;
  - права проверяются в домене по actor (защита в глубину);
  - аудит каждой привилегированной команды; step-up для `game.publish` и `wallet.adjust`;
  - пагинация; ErrorBody; Idempotency-Key для создающих команд;
  - события — outbox в той же транзакции; consumers — inbox с дедупликацией и проверкой издателя.
- **Тексты ученика и PII** — никогда в логах, событиях, метриках. Комментарий сотрудника к операции ученику не показывается.
- **Тесты на стенде:**
  - Python — `uv run pytest <каталог> -q -p no:cacheprovider`, `uv run ruff check <каталог>`, `uv run mypy <каталог>/src`. Каждый сервис — отдельным запуском;
  - TS — `npx vitest run`, `npx tsc -p tsconfig.json --noEmit`; фронт — ещё `npx playwright test`, `npm run build`.
- **Минимум тестов на эндпоинт:**
  - happy path, 401, 403 (чужой вызывающий и нет права, нет step-up), 404, 422, 409 (переходы статусов, баланс), идемпотентность, изоляция учеников;
  - события — `assert_event_conforms`;
  - гонки: две встречные заявки, два одновременных принятия вызова, закрытие недели дважды, повторный ход и переподключение в комнате;
  - удаление ученика под блокировкой (проверка «удалён?» после захвата блокировки ученика).
- **Перед сдачей** — внутренний QA-чек-лист:
  - IDOR (`member_id`, чужие комнаты, дуэли и отчёты), AuthZ, переходы статусов;
  - блокировки и санкции;
  - приватность в рейтингах и комнатах;
  - результаты закрываются один раз, переоценка сохраняет прежнюю запись;
  - повторная отправка;
  - граничные значения;
  - дети;
  - соседний сервис недоступен (social, lessons, ai-gateway) → понятная ошибка, учёба работает.

  Найденное исправь.

  - события;
