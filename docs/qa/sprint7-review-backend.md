## Проверено без замечаний

- `member_id`: HMAC одного формата в трёх сервисах, `user_id` наружу не уходит; `GET /members/{id}` доступен только gamification и lessons.
- Чужие комнаты, дуэли, заявки, санкции и сессии → 404.
- Админка комнат без текстов и оценок; модератор видит только предмет жалобы; отчёт ученика — только свой.
- Дети: ограничения в домене всех трёх сервисов (только семья, выбор реплик, без голоса).
- Блокировки и санкции проверяются в обе стороны (кроме п. 16); срок санкции — по времени.
- Лиги: закрытие недели атомарно, приз выдаётся один раз, позднее XP — в следующую неделю, обратные записи не уводят баланс в минус.
- Гонки: встречные заявки, двойное принятие вызова, повтор хода, переподключение.
- Контур: step-up и аудит у команд сотрудников; потребители проверяют издателя; голос не хранится; бюджет комнаты $0,10 соблюдается; роль support привилегированная (миграция 0007).

## Решения оркестратора по исправлениям

- **Рефералы спринта 6.** Никто не получает награду дважды и никто не теряет обещанную. `pending` спринта 6 доживают по старому правилу («первый урок за 30 дней»), затем тихо истекают. При `social.referral.qualified.v1` gamification не награждает тех, кто уже награждён по правилу спринта 6, и подтверждает закрытие. Месячный лимит учитывает награды спринта 6. Перенесённые в social рефералы помечены: диагностика считается пройденной, окно «3 урока за 2 дня» — от выкладки, истечение без уведомления.
- **Начальная загрузка проекций.** Единый контракт внутренних выгрузок `GET /internal/v1/export/<name>?cursor&limit` → `{items: [payload события], next_cursor}`: social — `families`, `friendships`; diagnostics — `levels`. Загрузка в gamification (и lessons, если нужно) — фоном при старте с отметкой завершения, вставка только при отсутствии строки, с учётом удалённых.
- **Парные уроки.** XP только за `finished` и ≥ 3 хода ученика, дневной лимит XP `pair_lesson`; лимит комнат с ИИ-коучем на ученика в сутки.

### Новые находки

**🔴 Н1. Подростки 14–17 с согласием родителя, полученным до выкладки, навсегда без общей лиги.**
- Где: `gamification/domain/projections.py:153` (`guardian_consent` — только из `user.profile.updated.v1`), `domain/leagues.py:137` и `:256`; `domain/bootstrap.py` (`SOURCES` без согласий); `identity-consent/.../service.py:987` (повторный запрос согласия при `granted` отклоняется).
- Сценарий: подросток получил согласие родителя раньше чем за 7 дней до выкладки (стрим хранит 7 дней) → в `learners.guardian_consent` NULL → `PATCH /v1/game/settings {league_opt_in: true}`: BFF пропускает (social считает друзей доступными), gamification отвечает 403 `FRIENDS_NOT_ALLOWED {reason: guardian_consent}`. Снова запросить согласие подросток не может (уже `granted`). Временный тест подтвердил 403. Нарушает решение владельца «общие лиги — 14+ по желанию» на prod-данных; данные не утекают (отказ безопасный).
- Предложение: добавить источник начальной загрузки согласий — выгрузку `profiles` из social (там `guardian_consent` есть со спринта 1) или identity-consent — в `bootstrap.SOURCES` с вставкой только при NULL; либо при включении участия перепроверять синхронно (social `GET /me/community` уже вызывается BFF — передать результат или вызвать из домена).

**🟡 Н2. Правило «доживания» `pending` спринта 6 — 30 дней, а в спринте 6 было 90.**
- Где: `gamification/settings.py:47` (`legacy_referral_days = 30`), `domain/tick.py:94`, `social_rewards.py:150`; в спринте 6 — `REFERRAL_VOID_DAYS = 90` (`docs/sprint6/INTERNAL_API.md:280`).
- Сценарий: приглашённый принят 45 дней назад, первого урока ещё не было → первый tick после выкладки → `expired`; урок позже наград не даёт. Временный тест: `[]`, статус `expired`. По правилу спринта 6 было бы +2 заморозки. Противоречит принципу оркестратора «никто не теряет обещанное».
- Предложение: `LEGACY_REFERRAL_DAYS = 90` (как спринт 6), либо явно подтвердить решение владельцем.

**🟡 Н3. Два источника месячного лимита рефералов.**
- Где: social — `monthly_cap` кампании (настраивается в админке), gamification — `rules.bonuses.referral_monthly_cap` (`social_rewards.py:117, 169`); `INTERNAL_API.md:213` («`bonuses.referral_*` больше не используются») противоречит `:418`.
- Сценарий: оператор поднял лимит кампании до 20 → после 10 наград gamification отвечает `inviter_capped`, пригласивший получает `referral_rejected monthly_cap`, хотя кампания разрешает. Месяц считается по времени обработки (gamification) и по `qualified_at` (social) — на границе месяца расходятся.
