### Новые находки повторной проверки

**🟢 T2-10 [admin-bff / admin-web, остаток T2-1] При сбое Redis или сети выход по-прежнему не завершает сессию, а UI показывает экран входа**

📍 `services/admin-bff/src/auth.ts` `loadSession`: для logout сессия читается из Redis до того, как стирается cookie, поэтому при сбое Redis ответ 503 уходит без `Set-Cookie`. `apps/admin-web/src/App.tsx:132-142`: `signOut` по-прежнему глотает ошибку `Auth.logout()` и переводит на экран входа. Так же ведёт себя сетевая ошибка или 502 от Caddy.

**Доказательство.** Скрипт ревью на обвязке admin-bff. Отключён только клиент Redis этого процесса, сервер Redis не трогали. `POST /auth/logout` вернул `503 UPSTREAM_UNAVAILABLE` без `Set-Cookie`, а ключ сессии в Redis после этого существует.

**Почему 🟢.** Пока Redis лежит, админка недоступна целиком. После восстановления сессия живёт не дольше 30 минут бездействия. Сценарий общего компьютера из T2-1 остаётся, но окно узкое.

**Рекомендация.** Для logout ставить `Set-Cookie` с очисткой до обращения к Redis: браузер теряет cookie даже при 503. В admin-web при 5xx или сетевой ошибке выхода не показывать обычный экран входа, а предупредить: «Выход не подтверждён сервером — закройте браузер».

**🟢 T2-11 [admin-web / admin.ts, остаток T2-2] «Отправить сейчас» берёт время из часов браузера**

📍 `apps/admin-web/src/screens/news/Campaigns.tsx`, `onConfirm` в `CampaignCommand`: `let sendAt = new Date().toISOString()`. Проверка «не раньше чем через 2 минуты» тоже идёт по `Date.now()` браузера. На сервере (`notifications/api/campaigns.py:271-279`) время от now−5 мин до now+1 мин означает «как можно скорее», раньше — 422, позже — отправка по расписанию.

**Доказательство.** Скрипт ревью: Playwright, `page.clock.setSystemTime(+10 мин)`. Подтверждение пишет «Отправка начнётся сразу после подтверждения», а в запросе `send_at` на 10,0 минут впереди реального времени. Сервер поставит такую рассылку в расписание на 10 минут позже.

**Последствия.** Если часы ПК спешат больше чем на минуту, «Отправить сейчас» молча откладывается. Если отстают больше чем на 5 минут, каждая попытка получает 422 и текст «Подтверждение заняло слишком долго». Вероятность невысокая: офисные ПК обычно синхронизируют время по NTP.

**Рекомендация.** Отдельный признак «как можно скорее» в контракте: `send_at: null` или `send_now: true`, время ставит сервер. Для «В выбранное время» можно учитывать сдвиг часов относительно заголовка `Date` ответа BFF.

**🟡 T2-1 [admin-bff / admin-web, сессия] Если admin-identity недоступен, выход не завершает сессию, хотя admin-web показывает экран входа**

> **Статус (повторная проверка, HEAD 35c3fd1):** ✅ **исправлено в 35c3fd1.** logout переведён на уровень `sessionOnly` (без principal и лимитов). Тот же скрипт: 204, cookie стёрта, та же cookie потом получает 401; после 70 команд — тоже 204; без CSRF — 403. Остаток при сбое Redis или сети — 🟢 T2-10.

📍 Где:
- `services/admin-bff/src/auth.ts:184-195`: onRequest вызывает `authenticate` для каждого сессионного маршрута, в том числе для `POST /admin/v1/auth/logout`.
- `src/auth.ts:115-125`: внутри `authenticate` principal запрашивается у admin-identity. При сбое запрос завершается 503 («fail-closed без отзыва»).
- `src/routes/auth.ts:161-178`: сессия удаляется и cookie стирается только в обработчике logout, а при 503 запрос до него не доходит.
- `apps/admin-web/src/App.tsx:132-142`: `signOut` глотает ошибку `Auth.logout()` и всё равно вызывает `toLogin`.

По той же причине выход не проходит при 429 `adm.command`: logout — это POST, и он попадает в лимит 60 команд в минуту (`auth.ts:112`).

**Доказательство.** Скрипт ревью: vitest на реальном Redis с обвязкой `services/admin-bff/test/helpers.ts`.
```ts
const { staff, s } = await loginAs(h, "support");
await redis().del(`${h.config.redisKeyPrefix}principal:${staff.staff_id}`); // кэш principal истёк (> 30 с)
h.fake.down.add("adminIdentity");
// POST /admin/v1/auth/logout → 503 UPSTREAM_UNAVAILABLE, Set-Cookie нет
h.fake.down.delete("adminIdentity"); h.clock.advance(5 * 60_000);
// GET /admin/v1/me с той же cookie → 200 (сессия жива)
```
Вывод прогона: `logout: 503 UPSTREAM_UNAVAILABLE set-cookie: (нет)`, затем `GET /me той же cookie после «выхода»: 200`.

**admin-bff: сессия и cookie**
- Cookie `__Host-tilhero_admin`: `Path=/; Secure; HttpOnly; SameSite=Strict`, без `Domain` (`cookies.ts`, тест). Max-Age после ротации равен остатку абсолютного срока.
- В Redis ключ — `sha256(id)`, данные хранятся в HASH. Бездействие 30 минут и абсолютный срок 8 часов проверяются по времени, ответ 401 `SESSION_EXPIRED`. Сессия привязана к User-Agent: при другом UA — `SESSION_REVOKED`.
- id ротируется при входе (прежняя cookie браузера удаляется — защита от фиксации), при step-up и смене пароля. Ротация атомарная, через Lua. Параллельный logout побеждает: новая сессия не создаётся. Старый id после step-up живёт 15 с без step-up и без продления, logout по любому из двух id удаляет оба.
- 409 `SESSION_ROTATED` приходит без Set-Cookie, домен при этом не вызывается и TOTP-код не тратится.
- Запрос с `X-Background: 1` не продлевает сессию. Смена `session_version` или статуса сотрудника → `SESSION_REVOKED` и удаление сессии. Кэш principal живёт не дольше 30 с и сбрасывается сразу при изменениях через BFF (PATCH, сбросы, approve).

- 401 вне шагов входа ведёт на экран входа; 401 `MFA_INVALID` и `INVALID_CREDENTIALS` в формах — нет.
- `STEP_UP_REQUIRED` открывает один диалог на все параллельные команды (singleFlight), запрос повторяется с тем же `Idempotency-Key`.
- `SESSION_ROTATED`: клиент перечитывает `/me` и повторяет запрос ровно один раз.
- 422 подсвечивает поле, вкладка нужного языка открывается сама.
- Фоновые опросы (дашборд, очередь, тред, рассылки, счётчик меню) идут с `X-Background: 1`.
- Таймер бездействия общий для вкладок через BroadcastChannel (передаются только отметки времени). Предупреждение показывается за 2 минуты, пока сотрудник активен, идёт heartbeat `GET /me`.

**admin-web: секреты на экране**
- Временный пароль хранится в `useEphemeral`: исчезает через 60 с, при скрытой вкладке, `pagehide` и размонтировании. После создания в состоянии остаётся `temporary_password: null`. При привилегированном сбросе пароль получает решающий в approve, автор его не видит.
- TOTP-секрет живёт только в состоянии `Login` и не попадает в URL, историю или хранилище. В URL бывают только UUID ученика и номер тикета.

**admin-web: раскрытие Telegram ID**
- `LearnerCard` смонтирован с `key={cardId}`, поэтому значение не переносится на карточку другого ученика.
- Значение пропадает из состояния по таймеру (не дольше 60 с, по `expires_in`) и при скрытой вкладке.
- Причина обязательна, от 5 символов. Без права кнопки нет. У детского профиля раскрывать нечего.

**admin-web: критичные действия**
- «Что нового»:
  - пустой перевод подсвечивается до сохранения;
  - сохранение блокируется проверкой клиента, при 422 сервера открывается вкладка UZ и подсвечивается поле;
  - «Опубликовать» недоступна, пока есть несохранённые правки;
  - 409 VERSION_CONFLICT показывает «перечитать»;
  - публикация и снятие идут со step-up и сохраняют ключ идемпотентности.
- Шаблон: активация и сброс — со step-up, сброс показывается только при активной версии. Тестовые получатели видны только масками.
- Рассылка: «Стоп» доступен в статусах `scheduled` и `sending` со step-up. Статистика опрашивается в фоне. Ограничение 30 дней есть (прошлое — см. T2-2).
- Four-eyes:
  - свою заявку нельзя ни одобрить, ни отклонить;
  - не-super_admin кнопок не видит;
  - `FOUR_EYES_SAME_PERSON` приходит от домена как есть;
  - решение принимается со step-up.

**admin-web: доступность**
- e2e `a11y.spec.ts`: у всех контролов 10 экранов есть имена. Tab доходит до меню и рисует видимое кольцо фокуса. Вкладки переключаются стрелками. Диалоги удерживают фокус и закрываются по Escape.
- Ячейки OTP подписаны, `autocomplete="one-time-code"`.
- Есть тесты контраста.
- Тексты ошибок RU/EN есть для всех кодов доменов спринта. Пропущен только dev-код `IMPERSONATION_NOT_ALLOWED`, он показывается общим текстом 403.

**telegram-bff, изменения спринта**
- `POST /v1/whats-new/seen` передаёт experience-config `lang` (locale аккаунта, как в for-me) и `age` (возраст активного ученика) для разрезов статистики.
- Если identity-consent недоступен, отметка ставится без сегмента (тест).
- experience-config принимает оба параметра как необязательные.
- Ученик без возраста считается `adults` — так же, как в for-me (документировано).
