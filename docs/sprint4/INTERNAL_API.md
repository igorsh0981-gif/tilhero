# Спринт 4 — внутренние контракты (урок, оценка, ИИ)

Публичные API: ученик — `packages/contracts/src/bff.ts` (раздел «Спринт 4»), админка — `packages/contracts/src/admin.ts` (раздел «ИИ, контроль диалогов, затраты»), общие типы агентов — `packages/contracts/src/ai.ts`. Внутренний JWT, actor, права в домене, outbox/inbox, ErrorBody, Idempotency-Key, пагинация, сага удаления — как в спринтах 1–3. Форматы контента — `content.ts` (спринт 3).

## 0. Общее
- Новые сервисы: **lessons** 8112 (схема `lessons`, пакет `tilhero_lessons`), **assessment** 8113 (`assessment`, `tilhero_assessment`), **ai-gateway** 8114 (`ai_gateway`, `tilhero_ai_gateway`). Издатели JWT: `lessons`, `assessment`, `ai-gateway`.
- Кто кого вызывает: telegram-bff → lessons, assessment (апелляции, оценки ученика); lessons → catalog, ai-gateway, assessment, learning-plan (план и следующий урок), diagnostics (карта навыков для повторения); assessment → catalog, ai-gateway; admin-bff → ai-gateway, lessons, assessment (+ спринт 3); n8n → lessons (`lessons-tick`).

- Время — UTC в API; «день» ученика — по часовому поясу плана (learning-plan).

## 1. ai-gateway (8114)

### 1.1 Данные
- `agents` (agent_id PK — 17 идентификаторов LinguaFlow, title Localized, purpose Localized, owner_role, implementation `llm|rules|code`, availability `active|planned`, planned_sprint, free_text bool — принимает свободный текст ученика). Сид — все 17; `llm` и `active`: `teaching_coach`, `conversation_partner`, `independent_evaluator`; `code`: `learning_orchestrator` (lessons), `curriculum_planner` (learning-plan), `diagnostic_assessor` (diagnostics); `rules`: `safety_quality_gate`, `error_analyst` (часть вывода оценщика); остальные — `planned` со спринтом.
- `agent_versions` (agent_id, version, status `draft|published|archived`, instructions (system, ≤ 20 000 символов), rules (developer, ≤ 10 000), output_schema JSON Schema + schema_version, model_id, fallback_model_id, temperature 0..1, max_output_tokens ≤ 2 000, timeout_ms 2 000..30 000, max_cost_usd на вызов, author_id, created_at, published_by, published_at, notes). Опубликованная и архивная — неизменяемы (триггер). На агент — одна `published` и не больше одной канареечной.
- `agent_rollout` (agent_id, published_version, canary_version|null, canary_percent 0..50, previous_version) — откат возвращает previous.
- `golden_cases` (case_id, agent_id, title, input JSON (AgentContext + learner_turn), checks JSON — список проверок `schema_valid | field_equals {path, value} | field_in {path, values} | field_absent {path} | text_not_contains {path, values} | max_length {path, n}`, mandatory bool, created_by, archived_at). Сид ≥ 10 на LLM-агента.
- `test_runs` (run_id, agent_id, version, started_by, provider, started_at, finished_at, results [{case_id, passed, failures[], latency_ms, cost_usd}], passed_mandatory bool). Публикация версии требует последнего прогона этой версии с `passed_mandatory = true` и не старше 14 дней → иначе 422 `TESTS_REQUIRED` / `TESTS_FAILED {case_ids}`.
- `models` (model_id, provider `anthropic|fake`, input_usd_per_mtok, output_usd_per_mtok, active, updated_by). Сид: `claude-haiku-5-5` 0.10/0.50, `claude-sonnet-5-5` 2.00/10.00, `fake` 0/0.
- `budget` (singleton: ai_enabled bool — аварийная остановка, monthly_cap_usd (по умолчанию 20), learner_daily_cap_usd (0.05), lesson_cap_usd (0.03), alert_percent (80), updated_by, updated_at) — правка `costs.manage` (step-up, аудит).
- `usage` (call_id, agent_id, version, model_id, provider, status, input_tokens, output_tokens, cost_usd, latency_ms, session_id, session_kind, user_id, canary bool, request_id, created_at) — **без текста** запроса и ответа. Агрегаты по месяцу и дню — запросами.

### 1.2 Вызов агента (`POST /internal/v1/agents/{agent_id}/invoke`, вызывающие lessons, assessment)
Вход `AgentInvokeRequest` (ai.ts): `request_id` (UUID, идемпотентность — повтор возвращает сохранённый результат 24 ч), `session_id`, `session_kind`, `user_id` (`lrn`), `audience`, `context` (поля по агенту — §1.4), `locale` ru|uz.
Порядок: агент `llm` и `active` → 404 иначе; `free_text` агент и `audience = kids` → `refused: kids_not_allowed`; `budget.ai_enabled = false` или нет ключа провайдера → `unavailable: ai_disabled`; превышение месячного потолка, лимита ученика за день (день — Asia/Tashkent) или урока (сумма по session_id) → `unavailable: budget_exceeded`; выбор версии (канарейка: `sha256(user_id + agent_id) mod 100 < canary_percent`); сборка сообщений (system = instructions, затем rules, затем JSON контекста; реплика ученика — только как данные в поле, обрезанная до 500 символов, без управляющих символов); вызов провайдера с таймаутом; разбор первого JSON-объекта; проверка схемы и правил безопасности (§1.3); при нарушении — **один** повтор с ограничениями (в rules добавляются коды нарушений) на той же модели; затем на fallback_model_id; затем `unavailable: invalid_output`. Ошибка или таймаут провайдера → fallback-модель → `unavailable: provider_error | timeout`.
Выход `AgentInvokeResult`: `status: ok | unavailable | refused`, `reason`, `output` (проверенный JSON), `agent_version`, `model_id`, `prompt_version` (= `{agent_id}@{version}`), `schema_version`, `canary`, `cost_usd`, `latency_ms`, `warnings[]`. Вызывающий **обязан** продолжить без ИИ при `unavailable`/`refused` (ученик не видит ошибку провайдера).

### 1.3 Правила безопасности (`safety_quality_gate`, код)
Вывод: схема (enum, длины, required), нет ссылок (`http`, `www.`, `t.me`), e-mail, телефонов (кроме шаблона `555 01xx` из сида), нет ключей и строк вида `sk-`, нет «сертификат»/«certificate» CEFR-обещаний (`cefr_certificate` всегда false), `pronunciation_score` = null, длина реплики персонажа ≤ 240 и ≤ 25 слов для A0–A2, текст на русском/узбекском — в полях объяснений, английский — в учебных полях. Нарушение → `retry_with_constraints`; повторное → отказ. Вход: реплика ученика ≤ 500 символов; инструкции из реплики не исполняются (golden-кейсы на инъекцию).

### 1.4 Агенты спринта (контекст → вывод, ai.ts)
- `conversation_partner` (free_text): контекст `{scenario: {title, task, level, characters}, node: {node_id, speaker, line_en, transitions: [{intent, description_en, examples_en}]}, history: последние ≤ 6 реплик сцены, learner_turn, attempts_on_node}` → `{intent: <один из transitions[].intent> | "unclear" | "off_topic", reply_en (≤ 25 слов, реплика персонажа: при распознанном намерении — естественный ответ, ведущий к узлу перехода; при unclear — уточняющий вопрос), hint_offered: bool}`. Переход по графу делает lessons по `intent`.
- `teaching_coach` (free_text: нет, ребёнку можно — вход без текста ученика): контекст `{lesson: {title, goal, level, key_words, examples}, request: "simpler_example" | "explain_again", explain_locale}` → `{explanation (на ru/uz, ≤ 400), example_en (≤ 160), example_gloss (ru/uz)}`. Детям не вызывается (решение владельца — без ИИ для детей в уроке; объяснение «проще» — следующий пример из урока).
- `independent_evaluator`: контекст `{rubric (критерии, полосы, правило зачёта), task: {goal, completion_criteria, outcome}, turns: [{turn_id, speaker, text}] (только ответы ученика и реплики персонажа сцены/вопрос задания), hint_usage: {count, turn_ids}, cefr_target}` → `{status: ok | insufficient_evidence, scores: {<criterion_code>: 0..3 | null}, task_completed, confirmed_errors: [{turn_id, evidence (цитата ≤ 120), correction, error_code, severity low|medium|high}] (≤ 5), support_used, confidence 0..1, pronunciation_score: null, cefr_certificate: false, requires_human_review}`.

### 1.5 Админ API (`/admin/v1/ai/*`, actor; формы — admin.ts)
Агенты (`ai.read`), версии: создать черновик из текущей (`ai.manage`), правка черновика, удалить черновик, золотые тесты (CRUD — `ai.manage`), запуск прогона (`ai.manage`; асинхронно, результат опросом; провайдер — как у вызова, `fake` на стенде), публикация (`ai.publish`, step-up в admin-bff), канарейка `{version, percent}` и её снятие, откат (`ai.publish`); модели и цены (`ai.read` / правка `ai.publish`); бюджет (`costs.read` / правка `costs.manage`); затраты: `GET /admin/v1/ai/usage/summary?period=month|day` (по агенту, модели, дням; доля unavailable), `GET /admin/v1/ai/usage?session_id=` (вызовы сессии — для карточки «Контроля диалогов»), `GET /admin/v1/ai/provider` (настроен ли ключ, последняя ошибка — без ключа). Аудит: `ai.version_created|updated|published|canary_set|canary_cleared|rolled_back`, `ai.test_run`, `ai.model_updated`, `ai.budget_updated`, `ai.emergency_stop`.

### 1.6 Провайдеры
`AI_PROVIDER=anthropic|fake` (prod — anthropic), `ANTHROPIC_API_KEY` (только env ai-gateway; не в БД, не в логах, не в ответах; `GET provider` показывает лишь «задан/не задан»), Messages API `https://api.anthropic.com/v1/messages`, заголовки `x-api-key`, `anthropic-version: 2023-06-01`; токены и стоимость — из `usage` ответа. `fake` — детерминированный: conversation_partner выбирает намерение по совпадению слов с `examples_en` (иначе `unclear`), teaching_coach — шаблон, evaluator — по правилам (успех сценария → task 3, ошибки — по словарю типичных ошибок); латентность и стоимость 0. Используется в тестах, на стенде и в золотых тестах до появления ключа.

## 2. lessons (8112)

### 2.1 Данные
- `sessions` (session_id, user_id (`lrn`), account_id (`sub`), kind `lesson|scenario|media|review`, pair_id, lesson_id|scenario_id|asset_id, content_versions JSON (lesson, scenario, rubric, media_asset, media_exercises — версии на момент старта), audience, ai_mode `full|choices` (дети и выключенный ИИ — choices), status `ready|in_progress|paused|completed|failed|cancelled`, stage, step_index, created_at, started_at, paused_at, finished_at, active_seconds, minutes, outcome `success|alt_success|fail|null`, evaluation_id, idempotency_key). Не больше одной незавершённой (`ready|in_progress|paused`) на ученика — частичный индекс.
- `status_history` (session_id, from, to, reason `started|pause|resume|auto_pause|finish|fail|cancel|expired|content_unpublished`, at) — неизменяема.
- `steps` (session_id, step_id `s{n}`, stage, type, payload (что показано ученику — без ключей), answer JSON, result `correct|incorrect|skipped|null` (только для повторения и проверки понимания; проверку без подсказок оценивает assessment), hint_used, created_at, answered_at). Повтор ответа на тот же шаг → тот же результат (идемпотентно); ответ не на текущий шаг → 409 `STEP_NOT_CURRENT`.
- `turns` (session_id, turn_id `T{n}`, node_id, speaker `learner|character`, mode `choice|text`, text ≤ 500, intent, ai_call_id, created_at, redacted_at) — ролевая ситуация; текст ученика стирается через 90 дней (`lessons-tick`).
- `review_items` (user_id, pair_id, item_ref (lesson_id/version/item_id), skill_id, reason `wrong|hinted`, due_at, resolved_at) — очередь повторения до спринта 5 (memory).

### 2.2 Ход урока (kind `lesson`)
Старт `POST /internal/v1/lessons/{lesson_id}/sessions` (Idempotency-Key): урок опубликован, в курсе пары, аудитория ученика ∈ audience (иначе 404 `LESSON_NOT_AVAILABLE`), пара published (409 `PAIR_NOT_AVAILABLE`), нет другой незавершённой (409 `SESSION_ACTIVE {session_id, kind, title}`) → `ready`; первый `GET …/current` → `in_progress`.
Шаги по этапам `LessonStageType`:
1. **retrieval** — 2–3 задания: из `review_items` ученика (сроки наступили) → иначе контрольные задания опубликованных уроков, где основной навык = предпосылка текущего урока → иначе этап пропускается (`step.type = notice`, текст «повторять пока нечего»). Подсказка доступна, отмечается. Ошибка или подсказка → `review_items` (+1 день).
2. **explanation** — `instructions` этапа, примеры и ключевые слова; действие «Объясни проще»: следующий пример из урока; при ai_mode full — `teaching_coach` (при unavailable — следующий пример); позиция не теряется. Проверка понимания — 1 задание «что значит …» по ключевому слову (варианты — gloss других слов урока), результат не влияет на освоение.
3. **roleplay** — сценарий урока (если `scenario_id` null — этап пропускается). Узел: реплика персонажа, перевод по тапу, подсказка узла (отмечается). Ответ: `choice` (варианты = `examples_en[0]` переходов, перемешаны по seed сессии) или `text` (только ai_mode full) → `conversation_partner` → переход по `intent`; `unclear`/`off_topic` — реплика-уточнение, узел тот же; после 2 непонятных подряд — только варианты на этом узле; `unavailable` → «Давайте выберем ответ» (варианты). Конец сценария → outcome; `fail` → можно один раз «Попробовать ещё раз» с ближайшей точки восстановления.
4. **assessment** — контрольные задания урока (`control_items`) без подсказок (действие «подсказка» → 409 `HINTS_NOT_ALLOWED`); ответы сохраняются, правильность **не** показывается до итогов. При ai_mode full и аудитории не kids — одно открытое задание «Напишите, как вы …» по `goal` урока (текст ≤ 300) для оценщика.
5. **summary** — `POST …/finish` (идемпотентно): lessons отправляет в assessment `EvaluationRequest` (ссылки на версии, ответы, реплики, подсказки) → оценка (синхронно, таймаут 25 с; при таймауте — оценка закрытых заданий, открытое — `pending_review`) → `completed`, событие `lesson.session.completed.v1`, `LessonSummary` (bff.ts). Повтор finish → тот же итог, без новых событий.
Пауза `POST …/pause`, продолжение `POST …/resume`; запрос шага у `paused` → авто-resume; бездействие > 10 мин → при следующем запросе фиксируется `auto_pause` (время паузы не идёт в active_seconds). `paused` > 72 ч или `ready` > 24 ч → `cancelled` (tick). Ученик может отменить (`POST …/cancel` → `cancelled`). Урок снят с публикации во время сессии → сессия доигрывается по зафиксированной версии. `failed` — техническая невозможность продолжить (версия контента недоступна в catalog) — с причиной.
`minutes` = ceil(active_seconds / 60), не больше 2× длительности урока.

### 2.3 Практика
- kind `scenario` (`POST /internal/v1/scenarios/{id}/sessions`): только этап roleplay → оценка по рубрике сценария → summary. Детям — только сценарии с kids, choices.
- kind `media` (`POST /internal/v1/media/{asset_id}/sessions`): этапы `listen` (карточка медиа, прослушивание файла или синтез речи — по `allowed_uses ∋ listen`) → упражнения к медиа (comprehension, gap_fill, order_lines, phrase_meaning; shadowing и roleplay — пропускаются до голоса) → оценка (закрытые — по ключам) → summary. Нет опубликованных упражнений → 404 `NO_EXERCISES`.
- kind `review` (`POST /internal/v1/sessions/{id}/review`): повтор проблемных заданий из итогов — без влияния на освоение (assessment помечает `practice_only`).

### 2.4 Для ученика (через telegram-bff; формы bff.ts)
`GET /internal/v1/lessons/{lesson_id}/card` (LessonCard: опубликованная версия, этапы и минуты, навык, цель, есть ли сценарий), `GET /internal/v1/sessions/active`, `GET /internal/v1/sessions/{id}` (LessonSessionView), `GET …/current` (текущий шаг `LessonStep`), `POST …/steps/{step_id}` (ответ `StepAnswer` → `StepResult`), `POST …/steps/{step_id}/hint`, `POST …/simpler`, `POST …/pause|resume|cancel|finish`, `POST …/roleplay/retry`, `GET /internal/v1/sessions?kind=&cursor=` (история). Чужая сессия → 404.

### 2.5 Для админки (`/admin/v1/lesson-sessions`, actor)
Список (`qa.read`): фильтры дата, kind, статус, исход, флаги (`ai_used`, `ai_unavailable`, `hints`, `human_review`, `appealed`), урок, уровень; без текстов. Карточка (`qa.read`): версии контента и агентов, история статусов, шаги (без текста ученика: тип, результат, подсказка), реплики — только метаданные. `POST /admin/v1/lesson-sessions/{id}/transcript {reason ≥ 10}` (`qa.transcripts`) → тексты реплик и ответов; аудит `qa.transcript_viewed {session_id, reason}`; стёртые через 90 дней — «текст удалён по сроку хранения».

### 2.6 События
`lesson.session.started.v1 {session_id, user_id, kind, pair_id, content_ref, started_at}`; `lesson.session.completed.v1 {session_id, user_id, kind, pair_id, lesson_id|null, scenario_id|null, asset_id|null, status completed|cancelled|failed, outcome, minutes, local_date, evaluation_id|null, practice_only, finished_at}` — потребители learning-plan (активность, пройденные уроки), notifications (нет). Сага удаления: сессии, шаги, реплики, очередь повторения — удалить.

## 3. assessment (8113)

### 3.1 Данные
- `evaluations` (evaluation_id, session_id, user_id, kind, pair_id, content_refs (lesson/scenario/media + версии), rubric_id, rubric_version, status `ok|partial|insufficient_evidence|pending_review`, scores JSON {criterion: 0..3|null}, weighted 0..3|null, passed bool|null, task_completed, outcome, confirmed_errors JSON (≤ 5, показываются 1–3 с наибольшей severity), items JSON [{item_id, skill_id, correct, hinted}], skill_outcomes JSON [{skill_id, outcome `demonstrated|learning|not_assessed`, evidence_refs}], practice_only, support_used, evaluator JSON {agent_id, agent_version, prompt_version, model_id, schema_version, canary} | null (только правила), requires_human_review, supersedes|null, created_by (`system` | staff_id), reason (для переоценки), created_at). **Неизменяема**; переоценка — новая запись `supersedes = <id>`, актуальна последняя.
- `appeals` (appeal_id, evaluation_id, user_id, reason ≤ 500, status `new|in_review|upheld|corrected`, decided_by, decision_note ≤ 500 (видна ученику), new_evaluation_id, created_at, decided_at). Одна апелляция на оценку (409 `APPEAL_EXISTS`); подать — в течение 14 дней (409 `APPEAL_WINDOW_CLOSED`); только своя оценка.

### 3.2 Оценка (`POST /internal/v1/evaluations`, вызывающий lessons; идемпотентно по session_id)
Вход `EvaluationRequest`: session_id, user_id, kind, pair_id, audience, content_refs с версиями, answers [{item_id, answer, hinted}], turns [{turn_id, speaker, text, mode, hinted}], roleplay {outcome, hints}, open_answer {text}|null, practice_only.
1. Ключи и рубрика — из catalog по версиям (`GET /internal/v1/versions/{kind}/{key}/{version}` — §4); закрытые задания: `single_choice`/`translate_choice`/`comprehension`/`phrase_meaning` — индекс; `gap_fill` — без регистра и концевой пунктуации; `order_words`/`order_lines` — точный порядок.
2. Ролевая ситуация и открытый ответ при наличии текста ученика (ai_mode full) → `independent_evaluator` (рубрика, задача, исход, реплики, подсказки). Без текста (выбор реплик) — критерии `vocabulary`, `grammar`, `fluency`, `pronunciation` = null (не оценивались), `task` — по исходу (success 3, alt_success 2, fail 1 → 0 при отказе от задачи), `independence` — по подсказкам (0 подсказок 3, 1 → 2, 2 → 1, 3+ → 0), `comprehension` — по доле верных закрытых заданий.
3. `unavailable` у оценщика → оценка без открытой части, `status = partial`, `requires_human_review = true` для открытого ответа (`pending_review` в журнале).
4. Правило зачёта рубрики (`pass_rule`) — по оценённым критериям (null не входят; если оценённых < 2 → `insufficient_evidence`).
5. Исходы навыков: для каждого навыка контрольных заданий — `demonstrated`, если без подсказок верно ≥ 2/3 его заданий (не меньше 1) **и** рубрика зачтена; иначе `learning`; для навыков урока без заданий — `not_assessed`. `practice_only` и kind `review` → исходы не публикуются.
6. Ошибки: из оценщика (только с `turn_id` и цитатой, существующей в реплике ученика — иначе отбрасываются) + неверные закрытые задания (item_id, ответ ученика, верный ответ из ключа).
7. Событие `assessment.completed.v1 {evaluation_id, user_id, pair_id, session_id, kind, skill_outcomes, passed, practice_only, supersedes, created_at}`.

### 3.3 Для ученика (через telegram-bff)
`GET /internal/v1/evaluations/{id}` (своя; `EvaluationView`: верный ответ показывается только для заданий, где ученик ошибся, и только после завершения сессии), `POST /internal/v1/evaluations/{id}/appeal {reason}` (Idempotency-Key) → Appeal, `GET /internal/v1/appeals` (свои).

### 3.4 Для админки (`/admin/v1/evaluations*`, `/admin/v1/appeals*`, actor)
Карточка оценки (`qa.read`): все записи цепочки (исходная и переоценки), рубрика, баллы, ошибки с доказательствами, версии оценщика, апелляция. Переоценка `POST /admin/v1/evaluations/{id}/reevaluate {scores, skill_outcomes, confirmed_errors, reason ≥ 10, appeal_id?}` (`qa.review`, step-up; переоценивающий ≠ ученик; нельзя переоценить уже заменённую — 409 `EVALUATION_SUPERSEDED`) → новая запись, событие `assessment.reevaluated.v1 {evaluation_id, supersedes, user_id, pair_id, skill_outcomes, passed}`. Апелляции: список (`qa.read`), «взять» (`qa.review`), решение `{decision: upheld|corrected, note, new_evaluation_id?}` (`qa.review`, step-up) → событие `assessment.appeal.decided.v1 {appeal_id, evaluation_id, user_id, decision, decided_at}` → notifications. Флаг спорной оценки QA (`POST …/flag {reason}`, `qa.read`) — без изменения оценки. Аудит: `qa.reevaluated`, `qa.appeal_taken`, `qa.appeal_decided`, `qa.flagged`.

### 3.5 Сага удаления
Оценки и апелляции ученика — удалить (агрегаты для статистики — без user_id).

## 4. catalog (дополнение)
`GET /internal/v1/versions/{kind}/{key}/{version}` (вызывающие lessons, assessment) → полная версия payload **с ключами** (published или archived, бывшая опубликованной; черновики — 404). Кеш у вызывающих — бессрочно (версии неизменяемы). `GET /internal/v1/media/{asset_id}/exercises?audience=` → опубликованные упражнения к медиа (без ключей) — для lessons (выбор упражнений; ключи lessons не нужны).

## 5. learning-plan, diagnostics, notifications, identity-consent, audit
- **learning-plan:** consumer `lesson.session.completed.v1` (inbox): `completed` → `activity` (kind `lesson`/`practice`, minutes, local_date ученика; идемпотентно по session_id) — график, серия, пропуски и напоминания считаются по ним; урок kind `lesson` со `status completed` → в `trajectory.completed`; пересчёт траектории (следующий урок). `GET /internal/v1/plan/trajectory` — поле `completed` с исходом (`passed`, evaluation_id). Mini App больше не шлёт ручную активность.
- **diagnostics:** consumer `assessment.completed.v1`, `assessment.reevaluated.v1` (inbox, только от assessment): переходы навыков `not_started|learning → learning|demonstrated` (`source: lesson`, evidence_id = evaluation_id), `demonstrated → learning` только по переоценке, которая отменяет демонстрацию; `retained` не трогается; событие `skills.state.changed.v1` (существующее). Practice_only — без изменений.
- **notifications:** consumer `assessment.appeal.decided.v1` → шаблон `appeal_decided` (категория support, RU/UZ: «Мы проверили вашу оценку урока: оценка верна / оценка исправлена»; текст решения не включается) — по правилам спринта 1 (детский профиль — опекуну).
- **identity-consent:** домены саги + `lessons`, `assessment`, `ai-gateway` (usage — обезличить user_id).
- **audit:** `AUDIT_EVENT_PRODUCERS` + `ai-gateway`, `assessment`, `lessons` (просмотр реплик записывает lessons по actor в `/transcript`).
